Sensory Shield — Privacy Policy

Applies to the Sensory Shield extension for Microsoft Edge, Google Chrome and other Chromium-based browsers. Last updated: 26 September 2026.

Short version. Sensory Shield has no server of its own. In its default local rule mode it makes no network request at all. If you switch on the optional remote rewrite mode and enter your own API key and endpoint URL, the text the extension extracted from the current page is sent from your browser to that endpoint, which you choose and control. No page content, key or usage data is ever sent to the extension's developer, and there is no analytics or telemetry of any kind.

1. What the extension handles

Item Where it goes
Page content of the tab you activate (article body text) Stayed in your browser in local rule mode. In remote rewrite mode, sent to the endpoint you configured (see section 3).
Your API key, model name and base URL (only if you use remote rewrite) Stored by your browser in chrome.storage.sync on your device and in your own browser profile's sync storage. Never sent anywhere except as the authorisation header of the request to the endpoint you entered.
Your choice of mode and per-page state Kept in your browser's extension storage on your device.
Browsing history, tab list, page content of pages you never activated Not collected, not read, not transmitted.

2. Local rule mode (default — no network activity)

In this mode the extension works entirely inside your browser. It hides page elements whose class or id matches its clutter keyword list (advertising, share bars, autoplay players, newsletter modals, decorative image rows), injects a low-stimulation stylesheet, and builds the summary card from the page's own text with a local rule set that drops opinionated or urgency wording and splits long sentences.

No request leaves your machine. You can verify this in your browser's developer tools network panel, or in the published source code.

3. Remote rewrite mode (optional — sends page text to your endpoint)

Remote rewrite is off by default and only becomes active after you open the extension popup, expand AI settings (optional), and enter an API key together with an OpenAI-compatible base URL. When active, this is exactly what happens:

  • The extension extracts the main body text of the page you chose to calm down. At most 8,000 characters per page are used; when the article is longer, the request carries only the first 8,000 characters and the summary card tells you the text was truncated at that limit.
  • That text is sent as an HTTPS POST from your browser to <your base URL>/v1/chat/completions — the endpoint string you typed in. The request includes your prompt and the extracted page text, and is authorised with the API key you stored locally.
  • The response (a rewritten summary) comes back to your browser and is displayed on the card. The extension does not store the response beyond the page you are viewing.
  • Because the endpoint is one you supply, that provider — not the extension's developer — receives the text, and it handles the data under its own privacy policy and terms. If you point the extension at a service you run yourself, the text never reaches a third party. If you point it at a commercial provider, that provider's retention and training policies apply; review them before enabling this mode.
  • Do not enable remote rewrite on pages containing sensitive personal data unless the endpoint you configured is one you are willing to send that data to. Local rule mode always remains available as a fully offline alternative.

Note: local rule mode only trims and re-splits the page's own wording, so its output reads as separate statements rather than fluent prose. The optional remote mode is what produces a rewritten text; the trade-off is the network request described above.

4. What the extension never does

  • No account, sign-in or registration.
  • No analytics, telemetry, crash reporting or advertising identifiers.
  • No selling, renting or sharing of data with data brokers.
  • No request to any server operated by the developer — the developer operates no servers for this extension, so it has no way to receive your data.
  • No injection of ads, affiliate links or sponsored content into pages.

5. Permissions and why they are requested

  • Read and change your data on all websites — the reading style and clutter-hiding rules must be able to run on whichever page you choose to calm down, and the optional rewrite request must be able to reach whichever endpoint you configure, including a self-hosted one. The extension has no server component and cannot know in advance which sites you read.
  • activeTab — limits the toolbar action to the tab you are viewing when you click the icon.
  • scripting — injects the reading style into that active tab when you press the start button.
  • storage — keeps your mode choice and, if you opt in, your API key, model name and base URL in your browser's own sync storage.

6. Your controls

  • Use local rule mode permanently: leave the API fields empty and the extension never makes a network request.
  • Remove stored credentials at any time with the Clear button in the popup, which deletes the key, model and base URL from chrome.storage.sync.
  • Disable or uninstall the extension from your browser's extension page; doing so removes its local storage.
  • Read or build the code yourself: github.com/TeWei02/sensory-shield.

7. Data retention

The extension itself retains nothing outside your browser profile. Text sent in remote rewrite mode is retained, if at all, by the endpoint operator under its own policy; the developer has no access to it, no copy of it and no way to delete it on your behalf.

8. Children

The extension is a general-purpose reading tool and is not directed at children. It does not knowingly collect personal data from anyone, including children.
